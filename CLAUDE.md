# Termy Code

Desktop client for ACP coding agents (Claude Code, Codex, Cursor, plus Grok, Gemini CLI as "Antigravity", and OpenCode). Tauri 2 + React 19 + Effect 4, package manager is Bun.

## Commands

```sh
bun install
bun tauri dev                                   # run the app (starts Vite on :1420 via beforeDevCommand)
bun tauri build                                 # release bundle
bun run build                                   # tsc typecheck + vite build of the frontend only
bunx tsc --noEmit                               # typecheck only
cargo check --manifest-path src-tauri/Cargo.toml
```

There is no test suite or linter configured. `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin; don't edit it by hand.

`termy_core` comes from the `termy-code/raw-pty` branch of termy, checked out as a sibling of this repo at `../termy-raw-pty` and linked by path, which adds `termy_core::pty` (raw PTY bytes for xterm.js, exit status, kill, per-command environment). Rust builds fail without it.

## Architecture

- `src-tauri/`: Rust. Spawns agents and pipes their ndjson stdio to the webview (`agent.rs`), runs shells on Termy's PTY for the terminal panel (`terminal.rs`), runs ACP `terminal/*` commands for agents on Termy PTYs with sanitized text output (`agent_terminal.rs`), stores and searches projects and threads in SQLite (`db.rs`), serves ACP `fs/*` requests and image attachments (`workspace.rs`), lists project files and agent skills for `@` and `$` mentions (`mentions.rs`), and resolves the login-shell `PATH` so GUI-launched agents can find `npx`/`agent` (`shell_env.rs`). Every command is registered in `lib.rs`.
- `src/services/`: Effect services. `Workspace` owns all app state (a `SubscriptionRef`) and agent session lifecycles; `AcpClient` wraps the ACP SDK; `AgentHost` turns Tauri events into an ACP stream; `Database` and `TerminalHost` front the Rust commands; `Tauri` is the single Effect boundary over `invoke`/`listen`/dialogs.
- `src/domain/`: pure types and reducers (session timeline, tool stacks, diffs, Cursor's `cursor/*` ACP extensions). Agent launch specs live in `domain/agents.ts`.
- `src/routes/`: TanStack Router file routes. UI primitives come from shadcn on Base UI (`src/components/ui`); the Notra registry provides shimmer and the step slider.

### How an agent session flows

1. `agent_spawn` (Rust) starts the process and emits `agent://stdout|stderr|exit` events tagged with a numeric id. `AgentHost` routes those by id into a `ReadableStream`/`WritableStream` pair (non-JSON stdout lines are dropped) and kills the process when its `Scope` closes.
2. `AcpClient.connect` builds an ACP `ClientSideConnection` over that stream. The client side of ACP (`fs/*`, `terminal/*`) is served by Tauri commands; permission prompts and `cursor/*` extensions are delegated to handlers supplied by `Workspace`.
3. `Workspace.ensureConnected` keeps one `Live` handle per thread (a `Scope`, a `ready` Deferred shared by concurrent callers, the pending user request). `establish` resumes, loads (replaying history, ignored while `replaying`), natively forks, or creates a new ACP session, in that order of preference.
4. Session updates go through `applyUpdate` in `domain/session.ts` into the thread's `Session` inside the `SubscriptionRef`. Requests that need user input (`Permission`, `Question`, `PlanApproval`) are set as `session.request` and block on a Deferred until the UI answers.
5. Threads are persisted once they contain a user message: the whole `items` timeline is stored as a JSON column in SQLite (search is a `LIKE` over title and items). Open tabs and each agent's last mode are kept in `localStorage`.

### React ↔ Effect

`src/lib/runtime.tsx` holds the `ManagedRuntime`. Components read state with `useWorkspaceState(select)` (a `useSyncExternalStore` over the `SubscriptionRef`; `select` must return stable references) and run actions with `useRun()`, which turns failures into toasts. Errors reaching the UI must carry a user-facing `message`.

# Learning more about Effect

This repository uses the Effect Typescript library.

Before writing any Effect code, first read `node_modules/effect/AGENTS.md`
**completely**, and follow the links in the file when required.

If you need to learn more about particular Effect apis and concepts that the
guide doesn't cover, search through the source code in `node_modules/effect/src`.
